# 디자인 자동 운영 (계속 업데이트)

4시간마다 실앱을 돌아다니며 디자인을 검사한다. **깨짐·가독성·에러는 바로 고치고, 완성도 개선은 제안→알림→승인** 순서로.

## 1. 두 트랙

| 트랙 | 대상 | 승인 | 실행 |
|---|---|---|---|
| **A · 자동수정** | 깨짐(오버플로·겹침·잘림), 에러(크래시·pageerror), 본문 명도 <4.5, 탭타겟 <24px, 폰트 <10, 줄간격 < 폰트, 제품규칙 위반(`code-check`) | 불필요 — 바로 수정·커밋 | 에이전트 세션 (4h 이슈에 증거 첨부되면 다음 세션에서 즉시 반영) |
| **B · 제안** | 팔레트·간격·타이포 스케일 변경, 새 컴포넌트, 카피 톤, 벤치마크 기반 리디자인 | 필요 — 이슈에 `/승인` 댓글 또는 `approved` 라벨 | 승인 후 에이전트 세션에서 적용 |

## 2. 검사 수단 (4시간마다)

- `scripts/design-check.mjs` — 정적: D1 본문명도(FAIL) · D2 보조명도(WARN) · D3 폰트 · D4 줄간격 · D5 하드코딩색
- `scripts/visual-check.mjs` — 실앱 주행: 6개 라우트 스크린샷 vs 베이스라인(픽셀 회귀 0.5%), 가로 넘침, 탭타겟, pageerror. 베이스라인: `docs/screenshots/baseline/<app>/`
- `scripts/livelike-check.mjs --smoke/full` — 사용성 주행 (클릭·게이트·상점규칙)

## 3. 벤치마크 (완성도 제안의 근거)

| 앱 | 참고 | 방향 |
|---|---|---|
| LiveLike | **스푼** | 라이브 오디오 UI — 방송 카드·리액션·기프트·댓글 흐름의 밀도와 리듬 |
| WorldWideSomeone | **젠리·인스타** | 친구 맵의 가벼움(젠리) + 피드·스토리·DM의 익숙함(인스타). 현 팔레트(v3)도 이 계열 |
| Beff | **젠리·제타** | 친구 맵(젠리) + 10대 채팅·관계 UI(제타)의 캐주얼함 |

제안 이슈에는 반드시 **현 스크린샷 vs 제안안 + 참고앱의 해당 화면 근거**를 첨부한다.

## 4. 승인·알림 플로우

1. 제안이 `design-proposal` 이슈로 열리면 Watch 중인 너에게 **GitHub 알림(이메일·모바일 푸시)** 이 간다.
2. 이슈 댓글에 `/승인` 이라고 쓰면 (`design-approve.yml`) `approved` 라벨이 붙는다.
3. `approved` 라벨 이슈는 다음 에이전트 세션에서 적용 → 스크린샷 증거와 함께 닫힘.
4. 반려면 `/반려 사유` 댓글 — 이슈는 닫히고 사유가 기록된다.

긴급(트랙 A) 이슈는 라벨 `auto-fix`로 열리고 승인 없이 다음 세션에서 바로 반영된다.
